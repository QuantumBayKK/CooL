CooL seals every change to an AI system — a prompt edit, a model swap, a
policy change, a granted tool — as a signed, tamper-evident record in a
transparency log. These docs cover producing those records and, more
importantly, checking them.

## Start with verification

The verifier is the part that decides whether anything else is worth doing,
so start there.

```bash
npm install -g cool-nwc
cool walkthrough   # the whole model, by doing it, in about three minutes
```

Then try the in-browser verifier at [/verify](/verify): it runs the real
`cool.receipt.v1` verifier on published conformance vectors and lets you tamper
with one byte to watch the exact domains fail.

## What the verifier reports

A verdict is never a single yes/no. Each domain is checked and reported on its
own, so a failure tells you what broke.

| Domain | Proves |
| --- | --- |
| `binding` | The record still hashes to the digest that was signed |
| `signature` | ML-DSA-65 and Ed25519 both verify over that digest |
| `inclusion` | The record is in the log under a signed tree head |
| `witnesses` | Independent parties co-signed the same log head |
| `attestation` | A TEE quote attests the key that signed |
| `enclave` | The measured image matches the pin you approved |
| `anchor` | The tree head was committed to a public chain |

<Note>
Off hardware — on a laptop, in CI, in a browser — the SDK runs a simulator and
the hardware-dependent domains report `simulated`, never `pass`. That rule lives
in the verifier. See [Limits](/limits) for what is and is not proven today.
</Note>
