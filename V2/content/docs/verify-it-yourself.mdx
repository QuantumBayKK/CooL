The claim this product makes is that you do not have to trust us. This page is
how you test that claim rather than accept it.

## In the browser

Open [/verify](/verify). It runs the real `cool.receipt.v1` verifier against the
published conformance vectors in [/cool-vectors](/cool-vectors/index.json).
Press **Tamper one byte** to flip one hex digit of a committed hash and watch the
exact domains fail; **Restore** re-verifies the original. You can also drop your
own receipt file — it is read locally and never uploaded.

## On your own machine

```bash
npm install -g cool-nwc
cool verify ./receipt.json
```

`cool verify` needs no enclave, no account and no network. It recomputes the
commitment, verifies both signatures, walks the Merkle path to the signed tree
head, and confirms the enclave quote attests the very key that signed. It exits
non-zero on any failure, which is what a pipeline gates on.

## Make it fail

A verifier that only ever says yes has told you nothing.

```bash
# 1. Edit one byte of the record, then:
cool verify ./tampered.json
#    binding and signature both fail

# 2. Demand a hardware root for a receipt sealed on your laptop:
cool verify ./receipt.json --require-hardware
#    rejected: attestation is simulated
```

`--require-hardware` makes a simulated attestation unacceptable. A receipt
sealed inside Intel TDX on Phala Cloud passes it; one sealed off hardware does
not, however many other domains pass.

## Check our hardware evidence

The Phala Cloud Intel TDX runs — raw quotes, receipts, verifier outputs and an
11-row tamper matrix — are published in the cool-sdk repository, with a script
that re-verifies every domain from those files. See [Evidence](/evidence) for
the summary and the reproduction commands.
